SERVER-SIDE AUTH
Short-lived tokens.
RTC, Signaling, and Chat user tokens use the official Agora token builder. The App Certificate stays on the server. Successful token generation does not prove that a service is enabled.
The App ID and App Certificate are required in .env. Tokens are not saved to disk or browser storage.

      
YOUR EVENT RUNBOOK
Configure, then connect.
  1. Before you leave
    Bring the event kit folder and Node.js 24+. It contains the built UI, contracts, and runtime dependencies. No keys are included.
  2. After receiving credentials
    Copy .env.example to .env. Add the App ID, App Certificate, and REST Customer ID and Secret when provided. These credentials are distinct, and one key may not enable every product.
  3. Enable selected services
    Set AGORA_LIVE_ENABLED=true, then run npm start. Add product-specific configuration for Chat, Whiteboard, or Classroom.
  4. Run a read-only test first
    Try the channel list or agent list. A 401 or 403 indicates a credential or permission issue; an empty list does not prove that media works.
  5. Feature test at cleanup
    Use two clients for voice and video. For AI, transcription, recording, and streaming, start → query → stop each task. Record task IDs and do not leave tasks running.
Native SDKs, hardware, partner callbacks, and specialized authentication require separate setup. The catalog is a coverage map and does not guarantee that every Agora product is enabled for the event account.
